## 模擬圓桌逐字稿（編寫示例）

以下發言全部由 AI 編寫，並非從參與者訪談取得。

**主持人視角（AI 模擬）**：「這次只練習既有 A。作者需要自己輸入欄位，我們要保留每次指令、錯誤、協助和四題回答；先看起始檔是否已留空，不能把預填正解當成作者完成。」

**作者視角（AI 模擬）**：「如果我只想輸入 2.5 秒，仍須找對 JSON 欄位、保留字串引號。我可能會把 `2,5` 當小數格式，也可能只看到 ready 就以為素材已檢查。這些是我預想的困難，需要真人操作才能知道是否真的發生。」

**工程師視角（AI 模擬）**：「M-01 證明 2.5 與 75 frames 的轉換一致、錯誤路徑可重播。不能由此得出介面易懂。有效而缺素材時回傳 exit 0 但未就緒；全部宣告有效仍只在宣告範圍。不能將結果接成執行核准。」

**研究審查者視角（AI 模擬）**：「H-01 是已接觸的維護者自操作，M-01 是機器資料，R-01 是同一 agent 的編寫。新作者原話與時間尚不存在。先做一名作者的質性觀察，固定順序並記錄協助；這不能推論秒數模式比影格模式快，也不能以舊 145 秒當本次對照。」

**主持人視角（AI 模擬）**：「下一步交給真人的只有作者卡與兩份留空起始檔；主持人答案留在另一份 README。先存四題原話，再討論解釋。若作者以為影片已驗證，保留這個反例，縮小提示設計，而不是把答案修成通過。」

## 本次結論與待驗證假設

- 已觀察：精確轉換、V1 原始診斷、缺件保留及宣告邊界在這八個案例中可重播。
- 待真人驗證 H-A1：去掉手寫 rational pair 是否真的減少作者輸入負擔；JSON 引號、欄位定位和錯誤修正是否仍造成失敗。
- 待真人驗證 H-A2：作者是否能辨別 exit 0、宣告就緒、媒體身分及宿主執行的不同意義。
- AI 建議：備妥下一個質性觀察；B 的精確 G2 決策、C 的媒體／隱私契約及 M3 authority 仍待維護者決定。本次沒有代填接受。

[未填真人紀錄](../../examples/evaluation/n10-06a-rehearsal/observation.blank.json)保留原題、起始資料、原話、現象及限制／使用性失敗五欄，另記同意、先前接觸、作者時間（包含 CLI 等待）、獨立程序時間、退出／未完成、協助、意外回答與作者確認。資料留在 Git 外，僅依明確同意發表匿名摘要或引文。真人證據狀態仍為 **待真人證據**。
