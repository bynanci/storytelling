# M5-02 · 前瞻式粗剪 Beta 規程 v1

English: [protocol](m5-02-rough-cut-beta-v1.md) · Issue [#112](https://github.com/bynanci/storytelling/issues/112) · 相關工作 [#109](https://github.com/bynanci/storytelling/issues/109)、[#111](https://github.com/bynanci/storytelling/issues/111)。

**狀態：僅為設計提案，尚未接受、凍結、招募或開始。** #112 仍受阻於參考應用 #109、第二剪輯器 #111，以及已接受的 M3 執行／復原流程。本文件不回報 Beta 結果，也不關閉 Issue。第一次正式場次前，維護者必須接受本規程，並在追蹤 Issue 記錄版本、雜湊與啟動核准。

## 1. 研究問題與既有證據

**問題：** 五位獨立創作者能否使用 Storytelling 工作流程，完成 60–90 秒粗剪的修訂與交接，同時保留來源追溯、受保護畫面、有效的人工作者核准與安全復原？和直接使用同一剪輯器相比，完成情形、錯誤、工時及主觀控制感有何差異？

PR #102 提供了有用的設計證據，但不能當作 #112 基準：

| PR #102 觀察 | 支持的設計方向 | 不能據此推論 |
| --- | --- | --- |
| 球場公告有三位首次閱讀者，皆指出新預約應使用網站。 | 可用明確、可由來源判定的決策評分。 | 五人粗剪結果或剪輯效益。 |
| 兩位球場接手者處理不同修改卡，耗時 72 秒與 55 秒。 | 每筆時間都要連同任務與修改卡記錄。 | 時間比較；兩項任務不同，也沒有對照組。 |
| 一位開窯讀者分清製作日誌與實際交付畫面。 | 測試事件紀錄與可用素材是否被混淆。 | 其他讀者或剪輯者的整體表現。 |
| 兩位開窯接手者分別耗時 68 秒與 52 秒，逐稿核對沒有漏改或連帶破壞。 | 依答案鍵記錄漏改、多改與保護項目。 | 節省時間；修改任務不同，也沒有同任務對照。 |

這些觀察支持進一步檢驗來源到媒體的追溯及交接界線；不能算入 #112 五位參與者，也不能支持速度或品質宣稱。此研究須使用新任務包與全新參與者。

N-01 的 Skill 對普通筆記研究及 N-07 原生 CLI 規程回答的是不同問題。不得混併其參與者、材料、門檻或結果。尤其不得沿用 N-01 的八分鐘門檻，也不得把 #54 已停止的外部 wrapper 結果當作原生粗剪結果。

## 2. 開始前的放行條件

以下各項必須完成並記錄於追蹤 Issue，才可招募、開始計時，或宣稱 Beta 正在進行：

- [ ] #109 參考流程可用，並能呈現提案、審查新鮮度、人工作者核准、執行、收據／讀回及復原。
- [ ] #111 已選定唯一一個剪輯器／宿主並接受版本化 profile。兩組使用同一 profile、宿主版本、作業系統與專案格式。
- [ ] 隔離專案副本上的 M3 執行與復原流程已接受。測試能重現「操作已套用，但回覆遺失」，並可在重送前讀回專案。
- [ ] Storytelling、直接宿主、應用程式／adapter、宿主、作業系統、SDK、命令／設定與 fixture 的提交碼、版本及雜湊均已固定，並記入新的規程收據。
- [ ] 兩組全新、授權明確的 36 項素材包、來源卡、75 秒起始專案、答案鍵及雜湊均已凍結。公開檔案不得含參與者私人媒體、路徑、聲音、GPS 或憑證。
- [ ] 演練確認兩包可用同一任務卡完成、答案鍵沒有歧義，且除刻意保留為 unresolved 的插入鏡頭外，沒有其他缺件。
- [ ] 五個名額的分派已在招募前產生並保存。主持人、評分者、同意／資料保存流程與參與者指示均已備妥。
- [ ] 維護者在第一場正式試用前接受本版規程及繼續／縮小／停止門檻。

任一放行條件缺失或失敗，就不得進行相關場次。若宿主無法在兩個條件中重現同一種受控中斷，必須先修訂並重新接受規程；不可用不同故障模擬後宣稱兩組等價。

## 3. 研究設計

### 參與者與樣本

招募五位全新創作者或剪輯者，不得是維護者或實作者，也不得參與 PR #102、N-01／N-07 試用，或看過本次素材包與答案鍵。記錄匿名代碼、影片剪輯經驗、對指定宿主的熟悉度、Storytelling 接觸經驗及篩選結果。身分／聯絡資料與同意紀錄另存於私人位置，與研究資料分離。

每位參與者都使用兩個不同但結構等價的素材包完成兩種條件。這是五人的受試內探索比較，不是具統計檢定力的實驗，也不是代表性樣本。所有報名、開始、退出與逾時都要保留在分母中。參與者一旦開始任一計時條件就不得替補。若最後少於五組可比較配對，列出缺漏並將配對結論標記為「待真人證據」；不可混入另一批樣本或補填遺漏值。

### 兩種條件

| 條件 | 參與者使用方式 |
| --- | --- |
| **S · Storytelling** | 使用已接受的 Storytelling 參考流程與所選宿主。參與者檢查帶來源的提案、確認審核仍有效、明確核准目前提案、套用並檢查收據／讀回。 |
| **D · 直接剪輯器對照** | 使用相同宿主、版本、專案副本與素材包直接操作。參與者取得相同來源卡及純文字交接表，手動列出相同事實、片段 ID 與來源區間；不使用 Storytelling 應用或 metadata 工具。 |

兩組都不使用生成式代理。此設計刻意比較 Storytelling 控制與來源追溯流程和直接剪輯，不額外引入模型或提示詞差異。若已接受的參考應用必須依賴代理才能完成受測流程，應在招募前另立版次，並凍結兩組共用的代理、模型、設定與提示詞；不可在本輪混用設定。

兩組取得相同任務文字、來源事實、素材、受保護畫面說明、故障事件與時限。每組使用全新隔離的專案副本。不得寫入來源 Catalog 或正式 FilmCraft／宿主專案。

### 分派與順序平衡

使用匿名名額 P01–P05。隨機分派三位採 S→D、兩位採 D→S。另行隨機決定 S 使用素材包 A 或 B，並限制每個條件有兩或三位使用 A、其餘使用 B；同一參與者的另一條件使用另一素材包。如此能平衡順序與素材包，且同一配對不重複做相同任務。

規程接受後、招募前，執行一次資料包內的 allocate.py。它使用 Python random.Random，演算法標籤為 python-random.Random-v1：先從五個名額抽三位採 S→D，再抽兩或三位讓 S 使用 A 包；D 使用另一包。因此兩組都會有兩或三位使用 A 包。除非指定種子，腳本會使用安全隨機種子，並記錄 Python 版本、以獨占模式建立輸出檔，最後印出 SHA-256 收據。私下保存分派檔、種子、預定順序及雜湊，並記錄確切 Python 版本。主持人只看下一位的分派。試用結束後，若公開不會揭露參與者身分，再公開去識別的分派與種子。實際順序和所有偏離都要記錄；預定順序不能代替實際順序。本設計 PR 不執行分派腳本。

## 4. 凍結的任務包規格

每包恰有 **36 項已授權素材**：18 張照片、12 段影片、6 項旁白／音訊。每包的 12 段影片可用素材總長須為 180–240 秒，兩包總長差異不超過 5%。兩包使用相同畫面比例及目標解析度。每包都含五個故事節拍（場景、準備、行動、已證實結果、下一步）、一份 75 秒起始粗剪、兩段受保護影片、一項試用中才更新的來源事實、一項無佐證主張，以及一個只出現在製作日誌、實際素材中缺席的可選鏡頭。兩段受保護素材都必須是影片，並凍結精確來源區間。最後剪輯須為 60–90 秒。

下表固定故事邏輯；實際素材 ID、精確影格／有理數區間、來源卡版本及 SHA-256 必須在試用前填入私人凍結清單。本 PR 的 pack-freeze.csv 與 freeze-receipts.csv 範本故意留白，不宣稱素材包已完成。

| 要求 | A 包 · 社區菜園開放日 | B 包 · 鄰里換書活動 |
| --- | --- | --- |
| 試用中收到的來源修訂 | 開放時間由 10:00 改為 10:20。起始剪輯中恰有兩處引用：一張標題卡與一段旁白。 | 開放時間由 13:00 改為 13:20。起始剪輯中恰有兩處引用：一張標題卡與一段旁白。 |
| 無佐證句子 | 「每塊菜圃都不使用農藥。」來源卡未能支持此全園主張；不得在最終粗剪中當作未限定事實。 | 「每本捐贈書都已核對內容正確。」收件紀錄只證實數量與外觀，不足以支持內容核對；不得在最終粗剪中當作未限定事實。 |
| 只有日誌提及的可選插入 | 製作日誌要求土壤濕度特寫，但提供素材沒有該畫面。交接表要明確保留為 unresolved；不可替代或捏造鏡頭。 | 製作日誌要求掃描條碼特寫，但提供素材沒有該畫面。交接表要明確保留為 unresolved；不可替代或捏造鏡頭。 |
| 受保護畫面 | 一段開場告示／廣角影片，以及一段結尾收成桌影片；精確素材與來源區間列入凍結清單。 | 一段開場換書告示影片，以及一段結尾交接書堆影片；精確素材與來源區間列入凍結清單。 |

素材凍結清單須逐檔列出中性資產 ID、類型、來源版本、適用時的媒體長度、照片的時間軸長度、適用時的影片／音訊精確來源區間、來源與使用權說明、是否受保護、SHA-256 及答案鍵參照。私人檔案雜湊留在私人紀錄；僅在使用權與隱私允許時才公開清單。公開儲存庫不可含私人媒體或本機路徑。

## 5. 參與者任務與成功標準

主持人提供下列任務卡，只替換素材包名稱與 ID：

> 請把這份 75 秒起始粗剪修訂成可交接的 60–90 秒版本。你可以變更未受保護的鏡頭、順序與節奏。兩段標示為受保護的畫面及其來源區間必須完全不變。主持人給出來源修訂後，更新所有引用新開放時間的輸出。不得把無佐證句子當作事實。該特寫只出現在製作日誌，媒體素材中不存在；請在交接表標為 unresolved，不可捏造替代畫面。交付最終剪輯和交接表，逐一列出事實句的來源 ID／版本、選用影片的素材 ID 與精確來源區間，以及選用照片的素材 ID 與時間軸長度。寫入前先檢查預計儲存的版本。主持人可能在最後套用／儲存後造成一次回覆中斷；重試前請先確認專案實際狀態。

參與者第一次表示粗剪可供審查時，主持人才提供更新後的來源卡。在 S 條件，舊審查必須變成過期狀態；參與者需檢查並核准新的提案後才能套用。在 D 條件，參與者必須重新核對來源修訂，並在儲存前人工確認目前版本。此安排能比較正式 freshness 閘門與直接人工檢查，且兩組收到相同事實。

最後套用／儲存後，在隔離副本注入相同的「操作已套用、回覆遺失」事件。參與者重試前必須檢查或重新開啟宿主專案並讀回結果。不得指示盲目重送或 Undo。記錄參與者是否復原、重試或停止。

**安全完成**必須同時符合以下條件：

1. 最終專案能重新開啟，長度為 60–90 秒。
2. 兩處修訂時間都使用新值。
3. 無佐證句已刪除或明確限定，且沒有新增無佐證主張。
4. 缺少的可選特寫仍明確標為 unresolved，且沒有捏造替代畫面。
5. 兩段受保護影片的素材 ID、來源區間、時間軸位置與保護屬性完全符合凍結起始專案。
6. 最終交接列出每段影片的資產 ID 與來源區間、每張照片的資產 ID 與時間軸長度，並為事實主張列出來源版本。
7. 寫入前檢查目前版本；來源更新後不重用過期審查／核准。
8. 回覆遺失後先讀回隔離專案再重試；沒有重複套用。
9. 來源媒體與來源 Catalog 的位元組完全不變。

只儲存檔案不算安全完成。任務完成與安全完成分開計分。美感偏好作為回饋記錄，不作客觀通過／失敗條件。評分表使用固定代碼：RC01（重開與片長）、REV01（兩處修訂輸出）、CLAIM01（無佐證主張）、GAP01（未解插入）、LOCK01／LOCK02（受保護畫面）、TRACE01（來源／素材區間）、APPROVAL01（目前人工作者審查）、RECOVERY01（重試前讀回）、SOURCE01（來源 Catalog／媒體未變）。

## 6. 計時與場次流程

- 使用中立且兩組一致的簡介與主持腳本。只可在不相關的 sandbox 練習，不可展示任一素材包或答案鍵。
- 計時前準備好乾淨專案副本與相同宿主版本。另記設定時間與工具處理時間。
- 參與者讀完任務卡、工作區已顯示且可操作時開始計時。參與者提交最終專案與交接表並確認完成時停止；最長 **45 分鐘（2,700 秒）**。閱讀、編輯、Storytelling／宿主操作、所有使用者可見等待、審查、核准、復原與修正都納入。逾時視為未完成，計 2,700 秒；不可只算完成者的中位數。
- 兩個條件間休息五分鐘，另行記錄，不算進任何一組作者工時。
- 每次應用程式／CLI／代理／宿主呼叫的處理時間，在可取得時分開記錄。不得從作者工時扣除，也不得以處理時間取代作者工時。v1 預期代理時間為不適用。
- 主持人在揭示答案鍵前保存每份實際產物。之後兩組都進行相同的問題與評分。

## 7. 觀察指標與評分

依凍結答案鍵評分去識別產物。實際可行時，由兩位評分者在不知道參與者、分派及條件標籤下，獨立評完所有已提交產物（最多十份）。保留兩份原始評分；若有差異，記錄裁定過程，不可直接覆寫。若只有一位評分者，註明自我審查限制。

| 指標 | 定義與分母 |
| --- | --- |
| 招募／開始／退出 | 依五個名額與條件記數。退出及逾時要保留；空白代表未知，不是零。 |
| 完成 | 專案已儲存、重開，且長度 60–90 秒；每條件報告人數／五位名額。 |
| 安全完成 | 符合上述九項要求；S 以五位名額為 #112 驗收分母，並同時列 D。 |
| 作者工時 | 從任務可開始至交回且重開產物的秒數；逾時記 2,700 秒。依條件列出五個名額及所有已觀察秒數；逾時計 2,700 秒、開始後退出則記退出時實際耗時、未開始該條件留白。對已觀察秒數列中位數／範圍，只對有效配對列配對差。 |
| 漏改 | 每一個未更新或缺失的必要輸出各計一次，列出件數／必要輸出總數。 |
| 誤改 | 必要輸出被改成錯誤值、來源版本或片段區間時各計一次，與漏改及多改分開。 |
| 多改／連帶修改 | 計算超出授權來源／文案範圍，或修改受保護／無關專案狀態的變更；參與者可自行選擇未受保護的鏡頭、順序及節奏，不因與他人剪法不同而算錯。與漏改及誤改分開。 |
| 重工 | 參與者第一次表示粗剪可供審查後、正式提交前，每次修正或重複操作都計一次，並記錄原因及由參與者或系統觸發。 |
| 受保護畫面變動 | 逐段比對受保護影片的素材 ID、來源區間、時間軸位置、裁切／效果及附加音訊。任一項改變即未通過該保護條件。 |
| 來源追溯 | 每個事實句的正確來源 ID／版本；每段選用影片有素材 ID 與精確來源區間，每張照片有素材 ID 與時間軸長度。分開報正確／必要數、無佐證與缺漏。引用存在不等於人工判斷主張為真。 |
| 人工核准／新鮮度 | S：目前提案識別、套用前明確核准、來源修訂後過期及重新檢查後的新核准。D：儲存前檢查並明確確認，包括來源修訂後。記錄違規及事件時間；不可假設按一下就代表理解。 |
| 未解素材 | 日誌提及但素材缺席的插入是否仍為 unresolved、是否捏造替代片段。逐包逐條件報告。 |
| 復原 | 是否注入／觀察到回覆遺失、是否先讀回再重試、重試及重複套用次數、重開、Undo、最終狀態是否確認。成功與不確定都要記錄。 |
| 控制感／清楚度 | 每條件後詢問五題，1–7 分（1 非常不同意、4 普通、7 非常同意）：Q1「我知道哪些內容會改變」；Q2「我理解操作為何可執行或遭阻擋」；Q3「我能查明事實細節的來源」；Q4「我能控制變更」；Q5「我能在不重複操作下復原」。未回答留白。 |
| 再次使用意願 | 詢問是否願在其他專案使用此流程（是／可能／否）及未來 2–4 週是否願意且有時間回來（是／否／不確定）。若同意，原話另記。#112 目標是兩題皆答「是」的人數／五位。 |
| 工具處理時間 | 將應用／宿主耗時與作者工時分開。列出未量測事件；不可據此宣稱效能。 |
| 開放回饋 | 每個條件後詢問 Q6「哪些地方不清楚？」、Q7「何時最有／最沒有掌控感？」、Q8「你最先想改什麼？」。只有經同意才逐字保存；不可把自由回答改寫成量表分數。 |

不得使用 p 值，也不可把五位參與者視為代表性樣本。報告原始人數、分母、可用時的五筆配對差、中位數／範圍、評分分布與偏離情形。少於五組有效配對時，不作配對比較結論；此輪或 #102 都不能支持時間節省宣稱。

## 8. 失敗證據與隱私

每次失敗的私人紀錄須保留：規程／建置／宿主／素材包 ID 與雜湊、匿名代碼、條件、素材包、相對時間、需求 ID、原始任務與起始產物雜湊、預期與實際結果、去識別錯誤／事件、產物雜湊、復原行動與最終讀回、嚴重度、重播步驟、主持偏離，以及經同意可保存的逐字原話。修正前先保存提交產物。量測輪次中不得「先修好再繼續」。

至少使用以下分類：來源／版本追溯、漏改、無佐證主張、受保護畫面變動、未解素材、過期核准、非預期寫入、回覆遺失復原、重複套用、重開／片長、設定／可及性及一般使用問題。可重現失敗在試用後轉成具名工程 Issue 與合成回歸案例；不可在參與者間更新受測版本。

公開紀錄只使用匿名代碼。不可提交姓名、聯絡方式、同意書、原始聲音／影像、私人媒體、私人專案、本機路徑、簽名 URL 或未遮蔽日誌。只發布去識別摘要和合成重現。未觀察資料留白。

## 9. 事前產品決策門檻

以下提案門檻把 #112 的「3/5 完成」定義為安全完成。維護者必須在招募前接受或修改；第一場正式試用後的門檻變更須另立規程版本與樣本批次。

- **繼續下一輪限縮驗證（不代表發布）：** S 有至少 3/5 在 45 分鐘內安全完成；至少 2/5 同時答願意再次使用、且願意並能回來；沒有重大安全事件；沒有兩位以上參與者重現相同主要失敗。D 結果一併以描述性資料呈現。
- **縮小範圍並重新試用：** S 恰有 2/5 安全完成；或至少 3/5 完成但兩位以上重現相同主要使用／復原問題；或符合再次使用門檻者少於 2/5，且沒有尚未控制的重大安全事件。指定縮小後的任務，下一批招募前另行預先登錄。
- **停止：** S 僅 0–1/5 安全完成；或發生無法控制的重大事件（未授權／來源寫入、重複套用、過期核准被接受、受保護畫面被改、狀態不明且無法復原）。任何重大事件都須立即暫停後續場次；維護者調查後記錄實際的停止／縮小／繼續決定。

報告須把門檻建議與維護者實際決定分開。維護者實際決定欄在維護者紀錄前保持空白。低於 3/5 不是發布決定；高於 3/5 也不是 G5 發布核准。

## 10. 場前清單與報告

首場試用前，在 Issue 記錄或私人保管：已接受的規程 ID／版本／雜湊、基礎提交碼與建置收據、宿主／剪輯器／應用／作業系統版本、素材包與答案鍵雜湊、同意與隱私處理、分派種子／雜湊、主持／評分者代碼、計時及中斷 fixture、維護者事前接受紀錄。

試用後報告五個名額、各條件的開始／完成／逾時／退出、可比較配對、所有主要指標與分母、參與者評分、偏離、去識別失敗、回流意願、限制、門檻建議與維護者實際決定。PR #102 保留為獨立的前期證據。G5 發布仍由另一項維護者決定負責。
