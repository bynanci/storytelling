Principal findings
1. The plan's G02 success fixture is NOT the fixture used by its named CLI/engine
   anchors. The named tests read n03-authoring-v1.json (revision 1). The plan names
   n03-author-reviewed-v1.json (revision 2, with C02). Use both or identify the
   intended case explicitly. Reviewed close-illustration brief contains the
   literal words '不放 C01 紅傘。'; assert that its SOURCE TAGS omit C01 and include
   C02, rather than asserting the prose contains no C01/紅傘.
2. G02 negative fixture/anchor paths also differ: invalid-dangling-reference.json
   changes beat index 1 (S99); the named CLI test dynamically mutates beat index 0
   (MISSING). Expect $.variants[0].beats[1].unit_ref.unit_id for the actual file,
   and index 0 for the test mutation. Do not copy one expected path to the other.
3. G06/G07 need a frozen PLANNER RESPONSE, not just the request listed in the
   plan. Review accepts {ok:true,planning:...}, not the request. The exact response
   bytes are embedded as selected_proposal_json and hashed. Re-serializing a
   parsed response, or independently computing two responses, cannot prove raw
   input parity. Freeze one original CLI response including its terminal LF.
4. CLI emit_bytes always appends one LF. SDK bundle_json()/compiled_otio() do not
   contain that presentation LF. Correct byte tests are CLI stdout == SDK payload
   plus ONE LF. Never trim arbitrary whitespace or parse/re-encode the artifact.
5. JSON envelopes differ intentionally: validate has {ok,validation}; plan-story
   has {ok,planning}; freshness has {ok,freshness}; coverage success IS the domain
   object and coverage failure is {error} without ok. Prepare emits a bundle
   payload. Preserve exact CLI stdout separately from domain comparisons.
6. Rich source-error byte serialization order can differ from the CLI's Value
   envelope (which recursively sorts keys). Compare complete parsed domain error
   objects for CLI parity and exact declared source serializer bytes for the SDK.
   Never compare SdkErrorV1 itself to a CLI ok/error envelope.
7. Changing only snapshot contentHash rejects with story_review.asset_mismatch;
   it does not produce Ok(stale). The existing CLI test's `current != true` also
   succeeds when freshness is missing. New tests must explicitly distinguish
   Err from Ok(current=false). A valid URI/context/cut change gives stale.
8. Selected review performs argument-order size preflight before any parsing;
   prepare then parses context before proposal, while check parses/validates
   bundle/profile/artifact before context/proposal compilation. Query validates
   change_id BEFORE reading the ledger. A generic shared preflight is incorrect.
9. SDK-G08's fixture inventory contains only three narrative/coverage failures;
   it does not by itself cover planner/review versions/profiles, full rich detail,
   null paths, limits, or compound order. Add the explicit mutations below.
10. G09/G10 have no concrete entries in cases[] or independent external consumer
   artifact. Add real tests and a standalone test-only consumer excluded from
   four-crate runtime workspace membership. Root doctests alone do not prove
   the documented consumer_v1 import path and curated nested types.
11. Plan metadata still cites 52dc6c3 and proposed/no implementation/no G2. Keep
   original fixture/blob identities and separately record actual base/head and
   the exact user design-adoption scope. Do not silently turn historical status
   into execution/Host/consumer-usability evidence.

Independent oracle rule
Every golden case should have a predeclared literal expected object/fields or a
tracked baseline output. SDK == backend, or SDK == freshly computed CLI output,
alone is self-consistency, not an independent oracle. Keep existing regressions
and predeclared fixed P1/P2 digests unchanged. For text, assert typed fields
directly and compare actual CLI bytes to an existing/full literal text golden;
do not parse prose back into a fictitious wire schema. New fixtures should be
new synthetic glue under MIT, without copying Apache test implementation text.

SDK-G09 ownership, immutable inputs, replay, concurrency, purity
Compile-only trait assertions T: Send+Sync+'static for every result and opaque
handle, SdkErrorV1, SdkEncodingErrorV1, and public supporting types. Do not demand
Clone/PartialEq from PlannedStoryV1/ValidationReport/opaque handle (not baseline).

mutable state; each exercises all eight operations, repeated successes plus
representative rejection. Compare to independently declared literals and frozen
goldens, not merely one worker to another. Limit concurrency/iterations because
budgets are per call. Retain before clones and assert every input buffer is equal
after success/error/threads, including bundle, proposal, snapshot, context, ID.
Run actual CLI with fixture files and stdin in sentinel temp directory, empty
external-tool PATH, compare recursive before/after snapshots. This complements
source dependency review; it does not alone prove absence of all side effects.
Cargo engine runtime dependencies remain serde,serde_json,core; four members.
New facade should contain eight direct delegates/error adapters and no filesystem,
network/model/clock/database/Host callback, executor/runtime/cache/background job.
