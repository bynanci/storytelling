2. Source-error serialization, code and path contract

Keep one private source enum with the five concrete payload types. Do not replace a source with a common {code,path} object or rebuild fields. source_details_json() should dispatch directly to serde_json::to_vec(&original_source). It returns the source object only, without operation metadata or CLI envelopes, and no trailing newline. A serde_json::Value round trip may reorder struct fields and is unnecessary.

A. storytelling_core::ValidationError
   Definition: crates/storytelling-core/src/lib.rs:21.
   Derives Debug, Clone, PartialEq, Eq, Serialize; implements Display and std::error::Error.
   Source serialized field order: code, path.
   Shape: {"code":"input.invalid_json","path":"$"}
   Both fields are required Strings. SDK path() = Some(source.path.as_str()). No omitted/null path.

B. storytelling_core::narrative::NarrativeValidationErrorV1

   relation_ids has #[serde(skip_serializing_if = "Vec::is_empty")]. Empty means ABSENT, not [] and not null.

4. Returned-type/serialization differences

- ValidationReport is Debug+Serialize only, with public fields schema_version, plan_id, assets, shots, scope. Do not add Clone/PartialEq as a shortcut for parity tests; compare fields/serialization.
- NarrativeProjectionV1 and its projection children are Debug+Clone+PartialEq+Eq, but intentionally have no Serialize or Deserialize. Do not add a JSON wire format to test them. Compare typed fields and leave existing CLI text formatting unchanged.
- Revision report/output records are Debug+Clone+PartialEq+Eq+Serialize. Event-result optional unit_id/from_revision/to_revision/variant_id omit absent fields; preserve that omission. NarrativeOriginV1 and NarrativeAuthorDecisionV1 serialize snake_case; matching them through the facade needs their names exported.
- Coverage result/output children are Debug+Clone+PartialEq+Eq+Serialize. Mapping optional asset_ref/source_range/reason omit absent fields, unlike coverage error.path, which emits null. Result struct field order is schema_version, profile, coverage_id, narrative_ref, asset_catalog_ref, selected_unit_refs, mappings, ready_for_planning, diagnostics; engine initializer order does not alter derive serialization order.
- PlannedStoryV1 and nested planner/brief/wire result types generally support Debug+Deserialize+Serialize but not Clone/PartialEq. These public DTOs are declarations, never trust handles. TargetStatusV1/SkippedReasonV1 serialize kebab-case.
- BoundStoryReviewV1 supports custom Debug and immutable accessors only; no Clone, Serialize, Deserialize, Default or public fields. Aliasing preserves all of that.
- ReviewRecordV1 and nested identity DTOs support Clone/Deserialize/Serialize and public field mutation on a caller-owned clone. This is intentional untrusted portable data, not a mutation path into the bound object or authority. ReviewFreshnessReportV1 is Clone/Eq/Serialize and contains only owned data plus a static scope.

- plan_story: size -> loose VersionProbe parse -> unsupported version -> closed Input parse -> brief audit -> hard conflicts -> catalog/candidate validation -> required candidates -> clocks/selection/order. Generic preflight would change existing semantics/error order. Brief errors/conflicts already have rebased paths.
- prepare_story_review: all input sizes in proposal -> snapshot -> context order BEFORE any parse; then parse/validate context -> proposal depth -> proposal parse/claims/selected-plan checks -> snapshot import/match -> compile/bind. 7. Ownership, concurrency and security observations

- Backend signatures borrow only input buffers and return owned Strings/Vecs/Boxes/static strings; returned results retain no input lifetime. This is source-inspection evidence, not a compiled Send/Sync proof.
- Visible field graphs have no Rc/RefCell, mutable global state, runtime handles, callbacks, Host leases or borrowed input data. Bound handles use owned DTOs and Box<[u8]>. Natural Send/Sync looks feasible without unsafe impls. Add compile-time trait assertions and caller-thread replay as implementation evidence.
- Do not add caches, global mutable metadata, spawned threads, cancellation/timeout semantics or optional privileged callbacks to the facade. Caller-owned thread pools determine concurrency; per-call bounds do not cap aggregate memory or guarantee allocation success.
- Drop has no rollback/cancellation meaning. No editor operation occurs, and a read-only result grants no writer lease.
- Keep core/engine pure: no filesystem, Tokio, database, network, model, clock or Host calls. Existing core hashing is pure supplied-byte hashing. Engine dependencies already are serde, serde_json, core; no dependency change is needed.
- Treat JSON content as untrusted declarations, including any URI/source text in snapshots and opaque JSON metadata. Such strings remain inert; the facade has no shell/path/URL opening operation.
- Raw OTIO/bundle output can intentionally retain supplied snapshot/proposal text and URI declarations. Avoid logging or publishing raw user inputs/outputs; public fixtures and reports must stay synthetic or publicly authorized. Existing bound Debug deliberately avoids raw artifact output.
- Do not re-export approval-verification or journal capabilities just because they exist elsewhere in the workspace. No execute, approve, dispatch, retry, recover, journal-write, arbitrary shell/path callback or Host handle belongs under consumer_v1, including feature-gated additions.
- The current draft-video-input feature must not enable a different consumer_v1 authority surface.
- Cargo workspace has four crates, package version 0.1.0-dev.0, publish=false; this task does not justify publication, a fifth SDK crate, transport/wire protocol, TypeScript binding, Host work or G5 claims.
