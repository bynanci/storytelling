## Entry and Rust bridge

- `storytelling preflight-video-coverage-input <FILE|-> [--lang zh-TW|en]` uses the existing opt-in CLI feature `draft-video-input`, which already forwards the same feature to the engine. Put the optional language flag after the input. Omission selects `zh-TW`. An invalid language, repeated flag or extra argument returns usage exit 2.
- Under that feature, expose `#[doc(hidden)] pub fn render_draft_video_preflight(bytes: &[u8], english: bool) -> (String, bool)` from the engine for CLI linkage. The first value is complete UTF-8 text with LF line endings. The second is declaration validity. `true` covers both the complete and unresolved valid results. The CLI maps it to exit 0 and maps `false` to exit 1. The CLI retains ownership of input reads and usage. A fallible stdout write keeps the bridged validity exit on success and returns exit 3 for I/O failure. The bridge remains outside the stable SDK facade. Row and hint types stay private.
- The existing `normalize_draft_video_coverage` takes the complete original bytes and returns an owned JSON success envelope or one error with `stage`, `code` and `path`. On success it provides both normalized declaration JSON and V1's `ready_for_planning` and `diagnostics`. On rejection it returns the first error and no partial conversions. B derives the authority block and validity from this method once, and prints a text preview. A's existing `--emit-v1` is the explicit route to declaration JSON. A raw byte count, UTF-8, syntax, duplicate-key or depth failure suppresses all rows and hints. A normalized V1 size/depth failure also suppresses the projection and keeps the original authority result. A usable wrapper has exactly `draft_version` and `coverage`, with the accepted version and a coverage object. Safely interpreted fields in such a wrapper may be shown after a conversion or V1 rejection. Rejected documents label advisory conversions tentative. ## References and advisory order

Preserve each selected index and original order. A displayable reference has an object with exactly `unit_id` and `revision`, a nonempty ASCII ID of at most 128 bytes with an alphanumeric first character and only ASCII alphanumerics, `.`, `_` or `-` thereafter, and a positive `u32` revision. These are display parsing rules. V1 owns existence, variant membership and freshness. For a malformed reference, print its fixed index and `Invalid unit reference` / `單元引用格式無效`; omit its untrusted fields and attach no mapping matches. Use the same rule when reading a mapping's `unit_ref`.

Match the complete `(unit_id, revision)` pair. Index mappings once in source order and list every matching mapping index. For repeated selected references, retain every selection row and point repeated groups to the first selection index with that full mapping index list. Render each mapping's details once, including unmatched mappings as their own index-ordered section. This preserves the complete match information without expanding identical index lists or reprinting source fields for every duplicate pairing. An invalid or stale mapping stays visible at its original index. Preserve duplicate matches and conflicting statuses for inspection. A selected reference with no exact match displays the missing row; omit that advisory when the reference itself cannot be interpreted.

Within the clearly labeled advisory block, group by mapping index, then by fixed logical field order `unit_ref`, `status`, `asset_ref`, `source_range.start`, `source_range.end`, `reason`. When there are range-wide findings about `unit`, `timing` or `fps`, place them before the endpoints under that range. Use A precedence among those findings. Frame input locations use `start_frame` and `end_frame`; their normalized V1 locations use `start` and `end`. Follow all mapping hints with selection's missing-row hints in selection index order. Unknown keys and their values stay undisplayed. Authority diagnostics keep their original code, path and order regardless of the number or order of hints.

A preview can display a declared duration only when the catalog contains one exact `asset_id@revision` match with a positive canonical V1 rational duration. Repeated exact matches give `Declared duration unavailable` / `無法確認宣告片長`. Mark all displayed duration evidence as declaration only.

Before projecting rows, cap both selection and mapping arrays at 512 items and the asset catalog at 1,024. If any cap is exceeded, suppress all advisory rows with `Preview omitted: too many rows` / `資料列過多，已省略預覽`. Limit the accumulated rendered advisory text to 4 MiB of UTF-8, counting escapes and labels before appending. If it would exceed the cap, discard the advisory block and print `Preview omitted: display limit` / `超過顯示上限，已省略預覽`. Neither suppression can change the authority block or the validity exit.

## Terminal text

Quote each displayed input string as data, escaping quotation marks and backslashes. Render C0 (`U+0000–U+001F`), DEL (`U+007F`), C1 (`U+0080–U+009F`) and bidi controls (`U+061C`, `U+200E–U+200F`, `U+202A–U+202E`, `U+2066–U+2069`) as visible `\uXXXX` uppercase hexadecimal sequences. For example, the CR in a supplied reason renders as `\u000D`, the C1 control as `\u009B`, and the bidi override as `\u202E`. Generated labels, indentation and line breaks belong to the renderer. Do not copy terminal controls, arbitrary parser messages, input file paths or unknown data into diagnostic labels or JSONPaths. The advisory text leaves the original bytes and A's decoded reason intact.

To replay, apply each case's edits to a fresh copy of its base fixture, or use its literal `raw_input`. Send that JSON over stdin to `storytelling draft-video-coverage-input -` and compare exit, stage, code and path for errors or readiness and specified diagnostics for success. Run the same bytes through `storytelling draft-video-coverage-input - --emit-v1`. For success, pipe the emitted declaration to `storytelling render-video-coverage -` and compare the result to A's `validation`. For rejection, compare the exact error stdout and exit across both A invocations.
