## Minimum semantics to preserve in a downstream audit

- **Manual choices remain hard requirements.** `compose` starts each beat's `required` set with `selectedAssetIds` (222), adds `must-include` IDs and all `asset-order` IDs (228–232), and assigns required selections before optional candidates. A required asset need not be inside `candidateAssetIds`; the candidate pool must not silently erase the selection. Downstream `manualSelectedIDs` may map to this membership guarantee. Upstream also treats their list order as hard order; omission of that ordering behavior must be explicit, not called parity.
- **Conflicting inclusion and exclusion fail.** Exclusions form a set (212–215). Every required ID is checked against it (248–253). This covers manual selection, must-include, and asset-order membership. Do not choose a winner, demote the manual selection into a preference, or discard it to make the request pass.
- **Missing IDs fail.** `compose` validates IDs from candidates, required selections, exclusions, and coverage groups against the media catalog (237–246), including an excluded ID that would not otherwise be used. Missing ordered IDs are covered because order IDs join `required`. Preserve the unavailable ID in a conflict report instead of filtering it away. `validateStory` separately rejects duplicate IDs within each ID list and checks references only when an asset catalog is provided; it is structural validation, not composition feasibility.
- **Ordering is partial-order conjunction.** `selectedAssetIds` supplies an order list (223–225); every explicit `asset-order` supplies another. `orderedAssets` adds adjacent directed edges from every list (787–788), optionally adds chronological edges, and topologically sorts. Adjacent repeated IDs fail (775–778); other repeated entries can produce a cycle. Cycles or chronology/manual contradictions fail (806–809). An order list also mandates the listed assets' inclusion. It is not merely a suggested ordering over whichever assets survive selection.
- **Chronology has exact source quirks.** It is enabled unless `enabled === false`; multiple chronological constraints are processed in order, so the last one determines the flag. Valid capture times sort ascending, unknown/invalid capture times behave as infinity, then asset ID breaks ties. Do not claim these details unless implemented/tested downstream.
- **Required duplication across beats normally fails**, with an explicit `allowEchoAssetIds` exception (262–270). A global brief audit without beats does not reproduce this ownership/echo policy.
- **Preferences can guide optional selection, not override requirements.** The source scores optional candidates (`scoreAsset`), allocates target-duration budgets, and checks hard minima/maxima. It has no general preference contract. A downstream preferences object or typed conflicts are original product design informed by the hard-selection policy; do not invent `sourceParity` for them.

For the bounded M2-01 layer, a successful audit should mean only that its implemented reference, inclusion/exclusion, and ordering checks found no conflict. It must not mean that a playable composition exists, target duration is achievable, all preferences can be met, or a planner proposal has been generated. If it evaluates an actual proposed ID list, absence of any manual/required ID is a hard loss/conflict, not a successful repair.

## Solver and planner boundaries

The real `compose` goes substantially beyond the audit: it rejects rejected/unusable required sources; assigns locked assets across eligible beats using bounded search; prevents unauthorized reuse; checks source capacity, beat/story duration bounds, coverage and visual media counts; backtracks scarce overlapping candidates; budgets clip lengths; merges order constraints; and returns a `Composition`. Its search limits produce errors, not proof of mathematical infeasibility. The simple audit must not be described as the solver.

`generateStoryPlanFromGraph` separately detects `precedes` cycles, unresolved alternatives, ambiguous paths, missing asset gaps, unsupported intent warnings, narration estimates, echoes, and scene-duration conflicts. It gathers selected/graph-linked media; it does not generically enforce all `StoryConstraint` rules. Missing selected media becomes `scene.gaps.missingAssets`, whereas composition rejects missing references. `compilePresetStoryPlan` adds authored-plan gates, including selected/required membership and exclusions (98–113); `storyFromPresetPlan` preserves source constraints and source manual ordering. None of these establish parity for a standalone brief audit.
