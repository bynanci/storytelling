## What actual exporter emits

The usable producer is `exportTimeline("otio", composition, assets, settings,
{preserveConfiguredFrameRate:true})`, called with that flag by real handoff
publication. Default exporter calls omit it and use `rateFraction` inference.

| OTIO node | Actual native fields / ownership |
| --- | --- |
| `Timeline.1` | composition id as name; `global_start_time`; `tracks:Stack.1`; owner metadata retains composition id/story id/settings/full original composition and compatibility report |
| `Stack.1` | named tracks, children in source track order, empty effects/markers, source_range for full composition |
| `Track.1` | source track id as name; kind Audio for audio/music else Video; children, empty effects/markers, source_range null; owner metadata retains source track type/timing |
| `Gap.1` | explicit nonnegative holes and trailing composition duration; retime padding is named/labeled separately |
| `Clip.1` | asset name as name; empty effects/markers; native source_range; owner metadata retains clipId, assetId, beatId, complete authored clip and native cut duration |
| `ExternalReference.1` | original asset URI exactly as target_url; asset name; available_range from source declaration (video/audio) or synthetic still hold; source identity/hash/reference facts in owner metadata |
| `TimeRange.1` | RationalTime start and duration |
| `RationalTime.1` | numeric `value = seconds * rate`, numeric `rate`; both use JS numbers in source, not decimal-string integers |

Source sorts a copied clip list by timelineStart, then `id.localeCompare` on ties.
M1-01 admits already ordered contiguous clips and unique IDs, so preserving that
array order is sufficient and avoids locale-dependent new sorting. It currently
admits no gaps/multitrack/audio/creative edits; M1-02 must not pretend it covers
source's broader profile unless the input contract is deliberately extended.

For stills, native clip duration is requested timelineDuration even if media has
no duration; its available_range is `[0, sourceIn + hold)`. For video/audio, native
cut duration is min(timelineDuration, source span), with labeled gap padding when
retiming's source excerpt is shorter. The current finite importer rejects retiming,
so no padding/linear-time-warp implementation is necessary for its first writer.

The source reference keeps URI encoding unchanged; it does not encode or open the
URI. A Rust serializer likewise must not fetch, canonicalize or resolve media.
Actual source-copy verification belongs to M1-03 or a real runtime adapter.

## Clocks: important differences, not interchangeable parity claims

1. Default `rateFraction` snaps near 24000/1001, 30000/1001, 60000/1001,
   120000/1001 (absolute tolerance <.001). Therefore source default OTIO turns
   29.97 into 30000/1001.
2. `preserveConfiguredFrameRate:true` leaves native rate exactly the source JS
   frameRate (29.97 remains that decimal). Real handoff publication uses this.
3. `createHandoffPlan` itself derives the raw decimal spelling with BigInt and
   only special-cases an exactly equal NTSC quotient, so the raw-29.97 handoff
   plan is 2997/100. Its integration test explicitly asserts this.
4. `resolveProjectTimebase` instead infers NTSC for legacy 29.97. Preserve original
   declaration and explicit timebase independently, as M1-01 already does.
5. OTIO native RationalTime numeric value/rate use floating-point representation;
   original M0 decimal-string u64 rationals cannot simply be placed into those
   numeric fields. JSON-number spelling alone does not make a value exactly
   representable in the official parser/host implementation.

The new G2 profile must choose and test an exact projection policy. Two coherent
small choices (root must choose, not silently combine):

- Project-frame clock: project each rational second value to numeric frames/rate,
  calculate/report any quantization loss, require the corresponding explicit loss
  choice, and preserve authoritative rational source clocks in owner metadata.
  Reject non-finite, overflowing, over-budget or otherwise unsafe projections.
- Exact finite content-clock representation: represent reduced n/d seconds by
  RationalTime value=n and rate=d, with both <=2^53-1, or use one bounded common
  integer tick clock; reject unrepresentable times explicitly. Different content
  clocks are legal OTIO, but they are not automatically a host/project FPS. Keep
  original project/display rate separate and test full sequence timing through
  official parser. Changing native clock units relative to source is intentional
  delta. A common tick clock must not be advertised as FilmCraft's frame rate.

In either choice, preserve original source snapshot as a JSON **string** under
namespaced owner metadata, plus exact rational source/plan clocks with integer
strings. Putting arbitrary M1-01 RawValue JSON directly into OTIO metadata can
normalize number lexemes and exceed metadata numeric limits on official
read/write (M1-01 admits u64 and opaque metadata numbers). A string can retain
authoritative original lexemes. Official read/write can upgrade schema labels;
compare semantic clips/ranges/URIs/metadata, not raw schema-version/object-order
equality when the parser upgrades representations.

## Loss/capability contract

`createHandoffPlan` actually uses native-editable / metadata-only / baked /
unsupported dispositions, per-owner feature/range/reason records, versioned
composition/mode/rate and always `realNleVerified:false`. It rejects unknown
composition/track/clip/transform fields and enforces independent resource limits.
It does not justify inferring generic host support from source's fixed exporters.

`otioCompatibilityReport` makes native cuts distinct from metadata-only visual,
audio-timing, retime, pin and lock semantics. Effects arrays remain empty when a
recipe is merely metadata. Pins/locks are never claimed to be enforced by a
foreign NLE. Baking uses runtime render/copy functionality in application, not a
pure OTIO serializer; do not label empty effects as baked/native.

M1-01 returns `audio.not_mapped / blocks-host-handoff` for every video, including
absent probe/audio metadata. A writer must not erase that blocker because a Video
track was emitted. Either keep the export blocked or require an explicit
picture-only loss choice, include it in the artifact/report, and still declare
host verification/execution false. Any extension for basic audio requires its own
frozen input/clock/profile contract; current importer rejects all audio tracks.

Similarly, M1-01 accepts original clip/track locks as source facts. OTIO has no
proven native enforcement for these; preserve them in owner metadata and identify
metadata-only lock behavior, with explicit loss choice where profile requires it.

Recommended first format profile is clearly named `otio-json` / versioned visual
cuts/stills, with required schema capabilities, empty native effects, no baking,
explicit source-clock mapping/loss choice, declared media references and unknown
host/version. It must keep `executable:false`, `hostVerified:false`; parser oracle
evidence belongs in validation records, not an unearned per-export verification
claim. Broader audio, effects and FilmCraft are independent follow-ups.

## Official oracle boundary

- official parse/write/read verifies schema, timeline/track/clip timing, URI/owner
  metadata, still holds, gaps, empty effects and retained compatibility report;
- actual file URI existence, SHA-256, ffprobe durations and decode bounds checks.

M1-02 can reuse the first category conceptually with independently authored
synthetic metadata and never dereference a supplied path/URL. It must not silently
perform the second category or claim those real-source checks passed. They need
authorized bytes and belong to M1-03. Official parser acceptance does not launch,
import into or certify FilmCraft/Resolve/any editor, render quality or listening.

Default Python in this workspace has no opentimelineio installed as inspected.
Install official pinned oracle test-only through the approved environment package
workflow; production Rust must retain no Python/FFmpeg dependency.
