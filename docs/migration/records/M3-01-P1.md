## Scope and evidence boundary

`prepare-review` derives an untrusted portable identity from the same bounded composition byte
slice passed into the existing importer and OTIO compiler. The private in-process `BoundReviewV1`
retains those exact serialized OTIO bytes. `check-review` parses the portable record as untrusted
data, recomputes a digest, recompiles the current composition and reports changes against the
caller-provided declared context. The record's four flags (`executable`, `approval_granted`,
`source_verified`, `host_verified`) are always false.

Three independent guarantees must remain separate:

1. A mathematically valid signature proves only that a message verifies against a supplied public
   key. It does not establish key trust or current signer authorization.
2. Trusted authorization needs a governed trust root, key-to-identity policy and revocation state.
   This slice has no signer or key verification and creates no authorization capability.
3. Artifact linkage here means the importer and OTIO compiler consume one exact provided byte
   slice, and freshness checks compile that current slice again. It does not prove the slice came
   from a verified build/source snapshot, nor does it connect planner output to the composition.

The context's project/revision, host identity/version/profile/binary hash/capabilities and loss
choices are declarations. No host is launched, no binary digest is observed, no media URI is read,
and no trust key, expiry, revocation, replay or one-use request store is consulted. M3-02 still owns
durable replay/idempotency and recovery; trusted grant issuance and execution remain future work.
