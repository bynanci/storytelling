## Security guarantees and limits

These three guarantees remain distinct:

1. **Mathematically valid signature:** a verifier proves that a supplied public
   key verifies a signature over the exact message. This P1 review-binding
   profile does not sign or verify anything.
2. **Trusted signer authorization:** this requires a governed trust root,
   key-to-principal/role policy, validity and revocation handling. This profile
   has none. The accepted decision here is a human maintainer decision recorded
   in this document; it is not a trust registry for runtime payloads.
3. **Binding to the actual compiled artifact:** this profile recompiles the
   exact composition bytes supplied to its builder and binds the resulting
   OTIO/report bytes. It does not establish verified source/build origin, that
   the bytes are the latest host state, or that the fixed-window planner
   produced that composition.

Portable records remain untrusted and forgeable consistency DTOs. There is no
signer authorization, trusted host observation, filesystem/TOCTOU guarantee,
expiry/revocation, one-use/replay protection, planner-to-OTIO bridge, editor
execution, publication or release claim. The approval/executable/source/host
flags remain false.

PR #28 remains its own unaccepted supplied-byte Ed25519 candidate. Its
mathematical signature verification does not prove trusted authorization or
that an artifact came from the same verified compilation. This sign-off does
not review, accept, or authorize PR #28.
