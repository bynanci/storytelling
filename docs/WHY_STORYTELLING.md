# Why Storytelling? 為什麼需要這個專案

同一場修門，社區報導可以從「誰扶住門、誰動手調鉸鏈」開始，插畫可以只畫兩雙手，口述則可以從結果講起：「這次，門關起來沒有磨到地面。」選哪個開場，取決於作者想讓誰理解什麼。若後來發現兩位鄰居的姓名寫反了，口述和有署名的構圖都要更正；只畫鉸鏈、沒有姓名標註的線稿可以照用。這兩個問題，一個關於敘事選擇，一個關於修改範圍，構成了本專案的出發點。

**產品假說。** 作者需要交付多個版本、和他人交接，或根據新證據改稿時，保留來源、版本與作者的取捨，有機會降低漏改和誤改。單篇小故事也可以直接寫完；一次性的邀請如果只需改一個日期，直接改稿更省事。哪些場合值得付出整理成本，是作者試用要回答的問題。[試用規程與普通筆記對照](narrative/N-01-AUTHOR-STUDY.zh-TW.md)

**English summary.** Storytelling helps an author decide what an audience should understand, choose a form that serves that intention, and revise the work when a source changes. Its strongest proposed use is a story with several versions or contributors. The portable skill supports drafting today. The project evaluates revision effort, attribution errors and author control separately from software correctness.

## 作者應該拿到什麼

| 作者要做的決定 | 一份稿子應該交付什麼 | 怎麼判斷可用 |
| --- | --- | --- |
| 說給誰聽，為什麼值得聽？ | 說得出對象、他原先知道什麼，以及希望他理解的變化、留下的疑問或可採取的行動。 | 找一位符合對象的讀者，用自己的話重述重點；作者判斷是否接近原意。 |
| 挑哪些片段，怎麼連起來？ | 在敘事需要時交代人物、意圖、事件與後果。把事件發生順序和觀眾得知的順序分開。原因不詳時保留未知。 | 打亂或刪去一個片段，檢查是否破壞必要線索。詩意拼貼可以保留開放聯想，公告可以開門見山。 |
| 同一材料有哪些值得比較的講法？ | 產出能實際比較的片段，例如兩個不同開場、兩張焦點不同的構圖稿，並說明各自適合哪個情境。 | 拿掉流派名稱，作者仍能指出先看到或聽到什麼、哪版適合受眾，並能保留、混合或拒絕提案。 |
| 哪些細節有根據，哪些是創作？ | 區分素材所載、作者詮釋與創作提議。訪談引語保留出處；圖稿新增的道具歸在指定版本。 | 抽查一個事實和一個新增細節，兩者都能說明來歷。引用存在與主張受到充分支持分別查核。 |
| 改一個細節後，誰要重看什麼？ | 交付修訂版本、受影響的項目及仍可沿用的項目。清楚標示交給配音員的是口播稿、交給畫師的是構圖，或已用工具實際產出的檔案。 | 編輯能找到漏改與多改，下一位製作者知道從哪份稿開始。真實影像、聲音或編輯器操作另以開檔、回聽或讀回驗收。 |

## 六個使用情境

下列是可重做的設計案例。驗收欄描述可找誰做什麼檢查，成效須由實際使用者提供。[八種可複製樣板](../skills/storytelling/references/multimodal-templates.md)

| 情境與任務 | 素材、敘事選擇與交付 | 驗收例 |
| --- | --- | --- |
| 家庭或日常口述：向沒到場的人解釋一次重聚 | 一段回憶＋一張舊照。用一個可觀察的動作開場，寫成 45 秒口述；缺少說話原文時改用轉述。 | 家人能分辨照片顯示的動作和講述者的感受；更正日期後找得出哪句需要改。 |
| 教育：讓第一次接觸主題的學生理解一次變化 | 一張過程圖＋前後兩筆觀察。先做線性講解，再做可自行選讀的兩張說明卡，各留下同一個問題。 | 學生能用圖說明變化，指出哪一步只是推測。卡片單獨閱讀時所需前提仍在。 |
| 紀實與 Podcast：把受訪者的猶豫留給聽眾 | 訪談、時間標記與授權範圍。比較「先播原聲」與「先說背景」兩版，交付引語、旁白與待錄 cue。 | 編輯能在來源中找到引語；沒有現場聲時，稿上清楚標記擬音提議。對外使用依已確認的授權範圍。 |
| 品牌或產品敘事：向使用者解釋一次改版 | 一則試用紀錄＋一段使用者回饋。用同一個使用困難寫產品公告及業務口述，將觀察與宣傳主張分列。 | 「這次試行由 10 分鐘降到 8 分鐘」可回查；擴寫成「所有人效率提升 20%」時應被標出。 |
| 劇本與分支構思：讓觀眾晚一步才理解角色選擇 | 兩個事件、一項人物目標、一個兩難。交付按事件順序與延後揭露的兩個開場，另列可選分支與後果。 | 讀者能說出何時得知關鍵線索。未選分支仍可回看；虛構情節與採用的來源素材分開。 |
| 跨通路交接：把工作坊做成海報與廣播 | 一則公告、一張示意圖與兩聲合成敲擊。海報以視線順序帶出日期；廣播用停頓分開音效與邀請。 | 把週六改為週日，核對所有提到日期的稿件；保留原圖與音效。實際素材與可比較的草稿見[修傘工作坊](../skills/storytelling/references/workshop-demo.md)。 |

## 研究如何影響設計

| 一手研究及其範圍 | 本專案採用的設計推論 |
| --- | --- |
| Zwaan、Langston 與 Graesser（1995）以簡短文字敘事的實驗，研究讀者如何依時間、空間、人物、因果與意圖把事件連起來。[原始論文](https://doi.org/10.1111/j.1467-9280.1995.tb00513.x) | 需要交代事件的作品，先請讀者重述「誰做了什麼，帶來什麼變化」。作者可依類型保留含混、跳接或開放結尾。 |
| Segel 與 Heer（2010）分析敘事視覺化案例，描述作者安排的閱讀路徑與讀者自行探索之間的取捨。[研究與案例](https://idl.uw.edu/papers/narrative) | 每個媒介各選一個可觀察的設計決定，例如海報的第一個視覺焦點、口述第一個線索。這是移用到其他媒介的設計假說。 |
| Lee、Liang 與 Yang（2022）的 CoAuthor 資料集記錄 63 位作者、1,445 場英文寫作。作者可要求、採納、略過或修改模型建議。[資料與互動設計](https://coauthor.stanford.edu/) | 作者提出、模型建議與最後採用分別記錄。在修訂驗收裡檢查被拒絕的細節有沒有回來。不能以採納次數代表滿意度。 |
| Masson、Zhao 與 Chevalier（2025）用兩次創意寫作原型研究檢視視覺化故事元素如何協助規劃修訂、追蹤元素和嘗試變體。[作者公開論文](https://damienmasson.com/pdfs/visualstorywriting.pdf) | 對一次改動，同時驗收該改的部分有沒有漏、無關的部分有沒有被改。用已知答案的小案例先做回歸，再觀察作者怎麼使用。 |

這些研究提供設計問題與測試方法。它們的研究對象、任務與媒介不同，無法據此推定 Storytelling 能提升故事品質、縮短創作時間或適用於每一種語言。

工程分工沿用既有架構。Skill 與作者決定內容和角度，core 表達型別與來源，engine 檢查明訂的引用、版本及順序，CLI 處理本機輸入輸出。作者判斷作品是否成立，以及內容是否適合發佈。V1 的來源關係只表示一筆宣告；歷史保存、可信度、授權與作品的情感效果各有獨立的證據需求。[架構](ARCHITECTURE.md) · [NarrativeDocumentV1](narrative/NARRATIVE_DOCUMENT_V1.md)

## 怎麼知道值得繼續做

N-01 已準備五人配對的試用規程。每位作者各用普通筆記與現有 Skill 做同一個限時修訂題，記錄完成數與分母、修改秒數、來源判斷錯誤與重複輸入次數。未來 Rust 工具另開一輪。繼續、縮小、停止的候選門檻與計時方式以[試用包](narrative/N-01-AUTHOR-STUDY.zh-TW.md)為準。試用表仍待真人填寫；工程測試通過也不構成作者效益的測量。

後續功能另有可重做的檢查，避免把喜好誤當成程式錯誤，或把通過測試誤當成作品成功。

- **N-04 修訂範圍。** 對一筆已知更正，先列應更新的版本，再比對實際輸出。分別列漏改與誤改的 ID。作者拒絕的提議保留原決定。
- **N-05 主張。** 拿掉關鍵來源，檢查受影響的措辭是否提出待查標記；保留其餘有佐證的內容。編輯自行核閱來源是否支持主張。
- **N-06／N-07 創作與交接。** 用同一份素材請讀者指出兩版最先傳達什麼、請作者解釋選擇、請下一位製作者指出還缺什麼。將這些觀察與機器結果分開記錄。若普通筆記即可完成、或分類反而增加錯置與重工，縮回已證明有用的情境。
