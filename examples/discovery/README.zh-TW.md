# 下一輪要找誰試用 Storytelling？

[English](README.md) · [情境總覽](../README.zh-TW.md)

小型編輯團隊往往有人寫稿、有人核稿、再由另一人發布或製作。來源更正時，三人要回答不同的問題：作者要改哪幾稿，審稿者要確認哪一句仍有根據，接手者要決定現有材料夠不夠交件。Storytelling 可以把三個問題留在同一份交接裡。若只有作者自己改一段文字，整理來源的工時也應算進成本。

## 從哪個問題開始

| 試用順序 | 誰遇到什麼麻煩 | 試完要觀察的決定 |
| --- | --- | --- |
| 先試 [預約服務公告](service-counter.zh-TW.md) | 值班編輯要說清楚，網站恢復接受新預約，電話目前只能查既有預約。交班時「部分恢復」很容易被寫成「全面恢復」。 | 居民讀完能選出已確認可用的管道，接班人也能分清三張查件收件單與實際預約結果。只要文字就能試。 |
| 接著試 [紀錄片的開窯鏡頭](kiln-coverage.zh-TW.md) | 拍攝日誌證實事件發生，剪接助理卻沒有能呈現該動作的鏡頭。導演仍想看兩種開場。 | 導演能指出哪一拍有文字根據卻缺畫面。助理交回補拍單時，仍把缺鏡列為待處理。 |
| 訪談選案 [四個探索情境](opportunities.zh-TW.md) | 公民科學編輯、會議紀錄人員、印務交接與劇場字幕操作，分別面對分母更正、提案狀態、同名異版檔案與現場觸發提示。 | 找得到實際負責決定的人，請對方拿最近一次重工說明後果，再決定哪一案值得製作完整試用包。 |

前兩案提供可複製的 A／B 內文、交接稿 C、來源與兩張獨立修改卡。後四案供訪談與選題。六案都是合成材料。原有 16 案仍使用其[既有評分表](../evaluation/keys.zh-TW.md)，這六案尚無真人交稿資料。

## 哪些已有依據

- **作者改稿。** 修門案例中，五位作者各做兩種條件，480 秒內完成的人數為普通筆記 3/5、Skill 5/5。維護者依私人試用紀錄決定在該任務繼續。新情境可以重新測量整理與改稿的總工時。[#48 試用紀錄](https://github.com/bynanci/storytelling/issues/48#issuecomment-6809944728)
- **觀眾讀法。** 修傘案例的兩位讀者均先 A 後 B，閱讀的是文字與聲音提示。維護者記錄了他們能辨識的焦點與一處不清楚的地方。新案例需保留第一眼的原話與稿內線索。[#65 盲讀紀錄](https://github.com/bynanci/storytelling/issues/65#issuecomment-6810251787)
- **接手與媒體。** 修訂查詢可列出直接引用該來源的版本，稿內相鄰句的含義仍要逐句看。影片對照能指出必要單元缺少已宣告的素材。開檔檢視影像與評估觀眾理解各自需要實際操作。[CLI 指南](../../docs/CLI_GUIDE.zh-TW.md) · [#67 影片交接紀錄](https://github.com/bynanci/storytelling/issues/67#issuecomment-6815393001)
- **工具版本。** 外部包裝工具的五位作者中，0/5 完成主要任務，5/5 出現重大歸因錯誤，維護者已停止該流程。固定版原生 CLI 的可驗證配對為零。這裡的文字演練可由主持人手動執行，原生 CLI 試用另有前瞻規程。[#54 決定](https://github.com/bynanci/storytelling/issues/54#issuecomment-6810253339) · [原生試用草案](../../docs/validation/n07-native-v3.zh-TW.md)

## 如何判斷是否值得繼續

1. **觀眾測試。** 先固定稿件、受眾、媒介與答案。把同一案的目標讀者分配到 A 先或 B 先，第一版作答後才給第二版。記錄第一個注意到什麼、能指出哪一句，以及接下來會做什麼。依版本分別報告「符合焦點人數／首次接觸人數」及「判斷正確人數／首次接觸人數」。
2. **接手測試。** 若要測來源邊界的額外價值，兩組都給相同三稿、修改卡與來源對照，兩組都看素材表的前兩欄，只有一組多拿第三欄的邊界說明。來源對照只抄稿號與來源 ID，主持人保留判準。替同一角色準備第二個難度相近的案例，再交換分派案例與條件、對調先後。球場公告與剪接簡報需要不同背景，應各自招募。每張卡從原稿開始。私下保存實際交回稿，逐稿記錄漏改、誤改及連帶改壞。新案先固定自己的答案，在私人試算表計分。既有計分器只認原來的案號。[原試用流程與分母](../evaluation/README.zh-TW.md)
3. **做產品決定。** 若觀眾能辨認兩種開場，卻仍選錯服務入口或錯把缺鏡判為可剪，先改訊息本身。若編輯少漏改，整理來源的工時卻高過省下的時間，先縮小需要標記的範圍。只有跨人交接反覆遇到同一個工具限制時，再提具體輸入、失敗交稿與預期結果供開發評估。[開發路線圖](../../ROADMAP.zh-TW.md)
