[English](README.md) · [完整規程與評分方式](../../../docs/validation/m5-02-rough-cut-beta-v1.zh-TW.md)

**目前只完成準備，未招募，也未宣稱 Beta 已開始。** #112 仍受阻於 #109、#111 與已接受的 M3 執行／復原流程。維護者接受規程且場前條件全數通過前，不可用這些表格記錄正式場次。

## 正式試用最短步驟

1. 閱讀完整規程，並在 #112 記錄維護者接受 m5-02-rough-cut-beta-v1 及其門檻。
2. 完成應用程式／宿主／M3 前置檢查。固定建置、剪輯器 profile、作業系統、SDK、fixtures 與故障注入方式。
3. 準備兩套全新、已授權的 36 項素材包、配對的 75 秒起始專案及答案鍵。填寫私人[素材凍結清單](forms/pack-freeze.csv)與[素材收據](forms/freeze-receipts.csv)，記錄兩包素材及答案鍵雜湊。儲存庫不含參與者媒體，也未填好凍結清單。
4. 以任務無關的 dry run 核對兩包、答案、時間及來源參照。dry run 不算參與者。
5. 規程接受後，從 repo 根目錄執行 python3 examples/evaluation/m5-02-rough-cut-beta-v1/allocate.py --output /private/path/allocation.json 一次；先建立私人目錄。把空白表複製到私人位置。同意書及身分／聯絡資料另行保存。
6. 招募五位符合條件的全新創作者；排除 PR #102、N-01／N-07 的參與者、實作者、維護者，以及看過素材包或答案鍵的人。
7. 每位參與者依分派順序完成兩種條件；每種條件使用新的隔離專案副本。每組最多 45 分鐘；所有使用者可見等待都計時。兩組注入相同的「已套用、回覆遺失」事件，必須先讀回再重試。
8. 揭示答案鍵前先保存實際產物。有條件時用兩位不知道條件標籤的評分者評分。缺漏保留未知，不填零。
9. 在每位參與者完成第二個條件後第 14–28 天，向已同意回訪者提供另一套凍結素材包的全新 S 專案場次。以 `forms/follow-up.csv` 記錄實際開始與安全完成；離場意願不算實際回流。
10. 僅公開匿名計數、去識別且可重現的失敗，以及維護者實際的繼續／縮小／停止決定。G5 發布另行決定。

## 凍結的對照設計摘要

- **S：** 已接受的 Storytelling 應用／流程，包含審查、目前版本的人工作者核准、宿主套用、收據／讀回及復原。
- **D：** 在同一剪輯器與版本直接操作，收到相同來源卡及人工交接表。
- 兩組都不用生成式代理。代理設定不同須在招募前另立新規程。
- 每位參與者在兩種條件都使用同一素材包與起始快照的新副本。隨機安排三位 S→D、兩位 D→S；A、B 兩包都須出現在兩種第一期條件中。
- 每包 18 張照片、12 段影片、6 項旁白／音訊；五個節拍、一份 75 秒起始剪輯、兩段受保護畫面、一項修訂事實的兩個相依輸出、一個無佐證主張，以及一段日誌有記載但素材缺席、須保留 unresolved 的可選鏡頭。
- #112 的主要完成門檻是**安全完成**，而不只是存檔：專案可重開且為 60–90 秒、來源修訂正確、沒有捏造證據、受保護畫面不變、審查核准有效，且重試前先讀回。
- 離場時再次使用的意願／能力與實際第二專案使用分開報告。14–28 天回流期結束後，至少兩人實際安全完成第二個 S 專案，才符合建議繼續驗證的回流門檻。
- 五人只提供探索性計數。分開報告隨機第一期兩組（3 對 2）與配對描述；第二期有重複任務練習效果，不得做顯著性檢定或宣稱節省時間。
