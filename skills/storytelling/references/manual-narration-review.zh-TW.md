# 透過宿主製作與檢視旁白

[English](manual-narration-review.md) · [Skill](../SKILL.zh-TW.md) · [聲音樣板](multimodal-templates.zh-TW.md#audio)

作者需要錄音或合成旁白，並希望挑選合適語氣時，使用這份指南。Storytelling 協助準備字稿、來源對照與檢視內容；操作者可在助理協助下，依作者既有授權明確呼叫製作工具。Storytelling CLI 不會合成聲音、操作這些宿主，或認證產物品質。

## 先界定一個小範圍請求

以下採用虛構工作坊素材，不使用私人錄音：

```text
使用 Storytelling 檢視一段工作坊旁白。
保留已提供的活動事實，並以作者偏好的早期試音作為比較。
準備一段短稿，指出實際需要執行的宿主操作。
記錄來源、字稿及輸出的版本。內容檢查與作者對聲線、語氣的判斷分開。
不要因為作者偏好短樣本，就替換整條旁白音軌。
```

預期交付可直接說出口的短稿、既有授權內的宿主操作與檢視紀錄。若缺少合適宿主或已授權的參考素材，先交付短稿與聲音提示表，將錄音保留為待完成。這是操作者的工作指引，不是新增 CLI 命令或自動 adapter。

## 每次試音保留對應證據

敏感證據留在作者私人專案內；對外討論使用中性的識別碼。

| 證據 | 操作者應記錄的內容 |
| --- | --- |
| 授權與來源 | 授權用途、來源識別、實際檔案雜湊、參考裁切區間及逐字稿版本。曾處理的副本不會自動成為原始錄音。 |
| 生成設定 | 工具與原始碼版本、模型與權重識別、相依套件、精度、seed、速度及參考設定。分別記錄展示文字與正規化後的模型輸入。 |
| 實際產物 | 輸出雜湊、原生取樣率與取樣數、量測時長、宿主操作、退出狀態及讀回結果。腳本時間碼在量測前仍是估計。 |
| 內容檢查 | 辨識器與設定、有無提供提示詞、估計字詞時間及待確認字詞。自動語音辨識（ASR）可標示漏詞疑點，但不能證明語氣自然或符合作者平常的讀音。 |
| 試聽與選擇 | 作者實際聽到的檔案、比較時的響度、回饋適用範圍與下一個已授權步驟。聲線相似、文字正確、語氣自然分開記錄。 |

manifest 宣告不等於位元組檢查；位元組檢查不等於試聽結果；宿主程序完成也不等於旁白通過驗收。試音更動後，重新檢查依賴它的字幕與時間安排，不沿用綁定其他輸出雜湊的檢視紀錄。

## 保留作者的選擇

1. 保留作者偏好的試音與設定。控制比較時，每次改一個相關因素。若同時更換引擎與參考片段，記錄兩者一起變動，不把差異單獨歸因於引擎。
2. 檢查實際音訊是否漏字或截斷句尾。ASR 疑點與已確認的錯誤讀音分開。不要把預期字稿作為辨識提示，再宣稱結果是獨立核對。
3. 使用相近響度的副本試聽，原生檔保留不變。整段變慢可能只是停頓變長，不代表句內說話密度降低。音高或音量都不能證明語氣輕鬆。
4. 依回饋實際範圍記錄偏好。偏好短樣本不代表接受完整段落或整篇旁白。既有授權可以涵蓋以選定聲線進行整份製作或審查輸出，不要重複要求同一項許可；仍須區分製作授權與作者是否已聽過並接受完整產物。
5. 作者選回初版時，找回該版的來源、參考與設定，保留已知的發音修正，包括依語境修正的文字正規化。明確記錄差異，不保證輸出完全相同。

在已授權製作或審查輸出中，依音訊實際量測安排字幕並保留原定留白，編輯驗收另行記錄。不要只為塞入舊腳本時槽而加速說話。已否決的試音維持否決狀態；換了模型或辨識成功，都不會覆蓋作者的選擇。

## 作者改為親自錄音時

將這項選擇視為新的製作指示。停止操作者自己建立的剩餘合成工作，並確認實際工作程序已退出。試音保留為排除使用的草稿，不要偷偷拿先前偏好的合成樣本補上缺句。

交付可直接照念的逐字稿，另外標示停頓、建議錄音時槽與不應預錄的內容。保留作者原有用語，區分建議時間與實測說話時間。繼續已授權的畫面及配樂工作，排除試音；將輸出明確標示為旁白待補的畫面優先版，不能當作已完成混音的最終影片。

收到作者的新錄音後，確認實際檔案、量測時間，再修訂相關字幕與配樂音量，保留原定留白。更換聲音來源不需要重做無關的畫面工作，也不需要再次索取已取得的製作許可。

## 限定宿主執行範圍

記憶體有限時，依序執行大型推論階段與渲染，先界定小型試音範圍。若本機監控器無法讀取記憶體或寫入收據，應停止自己建立的子程序並回報失敗，不能留下失去監控的工作繼續執行。不要擅自關閉其他應用程式。輪詢監控不是作業系統的記憶體保留；直接子程序清理也不保證管理任意後代程序樹。

外部寫入結果未知時，先讀回宿主狀態再重試。保留失敗與部分完成的收據。可攜工具可附固定版本的安裝指引與私人參考設定，不必塞入整個環境；稱為可重用前，先驗證解壓後的入口。不要把私人聲音設定與通用指南一起公開。

## 一次去識別化的操作觀察

一次個人旁白製作中，作者偏好早期短樣本的聲線，卻認為後續段落太像朗讀或速度太快。放慢生成的另一版仍未符合語氣需求。後來其他候選通過獨立文字辨識，作者仍選回初版聲線作為比較基準。這不代表接受整篇旁白。下一個檢查保留早期聲線設定，也保留已知的文字正規化修正。

之後作者改為親自錄音。操作者停止剩餘合成工作，保留試音但將其排除使用，改為準備錄音逐字稿與先完成畫面的交接；新的人聲錄音尚待收到後對時。這項調整保留作者最新的選擇，不把先前試聽偏好當作繼續合成的授權。

操作者另發現，監控器拋出例外時可能留下子程序繼續執行；後續檢查又發現，虛擬環境啟動器可能讓實際直譯器落在直接子程序清理範圍之外。因此改為先把暫停的 child 指派至私人 Windows Job Object，再恢復執行，並以實際自有後代程序測試逾時、guard 被終止、監控與儲存失敗。這些宿主端檢查與 Storytelling 驗證器分開。此經驗敘述不是經獨立重現的研究、模型排名、公開宿主相容性測試，也不是影片已完成的證據。私人媒體與逐字稿均不公開。

本指南補充 N-09／N-R09（聲音提示與估計時間）、N-11／N-R11（來源與修訂交接）、N-12／N-R12（實際宿主產物）的界線，不改動 schema、原生命令、任務驗收或發布狀態。
